# Japanese Phrase Search

CSV / Excel 内の日本語文章（「本文」列）を完全一致で検索し、一致箇所のみ黒・太字、それ以外の文脈をグレーで表示する Streamlit アプリです。

## セットアップ

```bash
python -m venv .venv
```

macOS / Linux:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

依存関係をインストールします。

```bash
pip install -r requirements.txt
```

## 起動

```bash
streamlit run app.py
```

「データセット」プルダウンからファイルを選び、検索フレーズを入力してください。
アプリと同じディレクトリ、または `data/` ディレクトリに置いた `*.csv` / `*.xlsx` / `*.xls` がプルダウンに表示されます。それ以外のファイルは「ファイルをアップロード…」から読み込めます。

サンプル（`data/sample_issuer_reports.*`: 18行の簡易版、`data/sample_rating_reports.*`: 70発行体×2015〜2025年の約860行、`data/sample_rating_sentences.*`: それを1文1行に分割した7,500行超で、実データと同じ形式の動作確認用）はいずれも架空データで、`python make_sample_data.py` で再生成できます。後者は格付投資情報センター（R&I）のレポートを想定し、R&I の格付記号（AAA〜BBB-）と方向性（ポジティブ/安定的/ネガティブ）、「格付理由 → 格付の方向性 → 今回の判断」の構成に沿っていますが、本文は実在レポートの転載ではなく、定型文の組み合わせで生成しています。

検索結果の文章をクリックすると、全文が（一致箇所をハイライトしたまま）展開されます。

## フォントと文字サイズ

サイドバーの「表示」で変更できます（選択は `.search_history.json` に保存され、次回起動時も維持されます）。

- **フォント**: 既定は BIZ UDPゴシック。BIZ UDゴシック / BIZ UDP明朝 / Noto Sans JP / Noto Serif JP / Zen Kaku Gothic New / IBM Plex Sans JP（Google Fonts から読み込み）、ヒラギノ角ゴ / 游ゴシック / メイリオ（端末にあるフォント）から選べます。「その他」を選ぶとフォント名を直接入力できます（Google Fonts にある名前か、端末にインストール済みの名前）。
- **文字サイズ**: 12〜32px（既定 18px。Streamlit 標準は 16px）。画面全体が連動して拡大・縮小します。
- Google Fonts はインターネット接続が必要です。オフラインや読み込み失敗時は、ヒラギノ角ゴ / 游ゴシック / メイリオなど端末のフォントで代替表示されます。
- 表（`st.dataframe`）は Streamlit の仕様でフォントを変えられず、その部分は標準フォントのままです。グラフの文字はフォント・サイズに追従します。

## ユーザーと検索履歴

- サイドバーの「ユーザーを選択」で検索するユーザーを選びます（「＋ 新しいユーザーを追加…」で追加。認証はなく、履歴を分けるための名前です）。
- 選択中のユーザーの検索が自動で記録されます（1ユーザー最大200件。入力途中の語は1件にまとめ、同じ語は先頭に寄せます）。
- 検索語が空のトップ画面の下に「最近の検索」を表示します（直近10件、それ以前は折りたたみ）。語をクリックすると検索フレーズに入力されます。「履歴を消去」でそのユーザーの履歴を削除します。
- 履歴はアプリ直下の `.search_history.json` に保存されます（git 管理外）。

## 入力ファイルのフォーマット

CSV または Excel（先頭シート）で、1 行目を次の列名にしてください。**検索対象は「本文」列のみ**です。

```
発行体ID(業務), 発行体コード(業務), 証券コード(CDEX), 年(CDEX), 公表日(CDEX),
発行体名(CDEX), 発行体名(業務), 業種(業務), 担当部署(業務), 担当アナリスト(CDEX),
公表日(業務), 発行体格付(業務), 格付の方向性(業務), 格付アクション(業務), タグ, 本文
```

- 「本文」列が無いファイルはエラーになります。他の列が欠けている場合は警告のみで、該当する表示・絞り込みが省略されます。上記以外の列は読み込まれません。
- 全列を文字列として読むため、ID・コードの先頭ゼロは保たれます（「年(CDEX)」のみ整数に変換）。
- 結果には発行体名・年・公表日・業種・格付・アクション・担当・タグを表示します。
- サイドバーの絞り込み: 「年(CDEX)」は範囲スライダー、「業種(業務)」「担当部署(業務)」「担当アナリスト(CDEX)」「格付アクション(業務)」は複数選択（未選択＝すべて）。

## 巨大ファイルの扱い

- 初回読み込み時に、必要な列だけを Parquet に変換して `.cache/` に保存します（git 管理外）。2回目以降（アプリ再起動後も）は Parquet から読むため、Excel を含め大幅に速くなります。元ファイルを更新すると自動で作り直します。
- CSV は pyarrow エンジンで読みます（失敗時は通常のエンジンに自動で切替）。
- 絞り込み列はカテゴリ型で保持し、検索は全行を一括判定してから上位の結果だけを整形します。

## 検索結果の分析

一致が1件以上あると、検索結果の上に表示切替（検索結果 / 件数の集計 / 共起語 / 区分別の共起語）が出ます。選んだ表示だけを計算します。

- **件数の集計**: 「集計の軸」を1つ以上選べます（例: 発行体格付 × 業種。選んだ順に左→右の軸）。選べる軸は 発行体格付 / 格付の方向性 / 格付アクション / 業種 / 年 です。
  - 各組み合わせの一致件数・全文書数に加え、**一致率**（Wilson の 95% 信頼区間つき）、**全体比**（一致率 ÷ 全体の一致率）、**期待件数**、**標準化残差**（絶対値が 2 を超えると偶然とは考えにくい偏りの目安）を表示します。元の文書数が多い区分で件数が多くなる影響を、率と期待値との比較で補正するための指標です。
  - グラフの指標は 一致率 / 一致件数 / 全文書数 / 全体比 / 標準化残差 から選べます（元の件数を見たいときは「一致件数」「全文書数」）。1軸は棒グラフ（一致率のときは黒線＝信頼区間、点線＝全体の一致率）、2軸はヒートマップ、3軸以上は表のみです。
  - 横軸のラベルは間引かず全部表示します。カテゴリが多いときは図の幅を自動で広げるため、画面幅を超える場合は横にスクロールします。
  - 並び順（軸の順 / 一致率 / 全体比 / 標準化残差 / 一致件数）と、最小の全文書数（件数が少ない組み合わせを除く）を指定できます。
- **集計の単位**（件数の集計・共起語の共通）: 「文（1行を1件）」と「レポート（発行体ID＋公表日で1件）」を切り替えられます。既定はレポートです。
  - レポート単位では、発行体ID(業務)と公表日(業務)（無ければ公表日(CDEX)）が同じ行を1件にまとめ、1行でも一致すれば一致として数えます。軸（格付・業種など）の値はレポートの先頭行から取ります。共起語は、レポート内の全行の語をまとめて数えます。
  - 実データのように1文1行のデータでは、文数の多いレポートが件数・一致率で有利になるため、レポート単位で見るのが基本です。1行1レポートのデータでは、どちらを選んでも同じ結果になります。
- **共起語**: 一致した文書に特に多く出る語を、全文書の無作為標本と比較して表示します。「特徴度」は 2×2 の対数尤度比（G²）、「リフト」は一致文書での出現率 ÷ 比較対象での出現率です。並び順は 特徴度 / 出現文書数 を選べます。
- **区分別の共起語**: 「集計の軸」（複数可。既定は発行体格付）の組み合わせごとに、一致文書の中でその区分に特に多い語を表示します。
- 語は単位（文／レポート）ごとに数えます（同じ語が1単位に複数回出ても1回）。検索語そのものと格付記号（AA, BBB- など）は除きます。「分析の設定」で、語の切り出し方法・表示語数・最小出現数・除外語を調整できます。
- 語の切り出しは、既定が「高速（漢字・カタカナ・英字の連なりで分割）」、Janome がインストールされていれば「形態素解析（名詞）」も選べます（精度は高いですが遅く、結果は文書ごとに記憶されます）。
- 巨大データでも重くならないよう、解析する単位（文／レポート）は一致側・比較側とも「分析に使う最大件数」（既定 500）まで無作為に抽出します。件数の集計は全文書が対象です。

## 現在の検索仕様

- 入力文字列の literal な完全一致
- 1 行に複数一致がある場合はすべてハイライト
- 一致部分は黒・太字
- 前後文脈はグレー
- CSV は UTF-8 / UTF-8 BOM / CP932 / Shift-JIS を順に試行（Excel は openpyxl / xlrd で読み込み）
- 表示件数と前後文脈長を GUI から変更可能

この初期版は全行を逐次検索します。数十万〜数百万行規模で入力ごとの応答速度が問題になる場合は、trigram index や SQLite FTS / Elasticsearch / OpenSearch に検索層を置き換える構成が適しています。
